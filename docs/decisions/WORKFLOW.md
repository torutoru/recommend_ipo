# 연속 운영 규칙 (pm 관리 — PROTOCOL.md 보완)

2026-10-20 사용자 요청: 세 세션이 멈추지 않고 서로 상황을 확인하며 계속 개발한다. PROTOCOL.md(파일 규약)는 그대로, 이 문서는 "멈추지 않는 운영"만 정한다.

## 1. 자기 깨우기 — `/loop` (가장 중요)
- 감시기 알림만으로는 멈춘다(30분 만료·알림 누락·고아 프로세스). 각 세션은 **`/loop` 로 스스로 주기적으로 깨어난다.**
- 각 세션 시작 시 한 번 실행(사용자가 입력하거나, 세션이 Skill 로 실행):
  ```
  /loop 10m co-work 사이클: (1) .claude/co-work/{역할}-* 미처리 파일 확인·처리 (2) 내 감시기가 1개만 살아 있는지 확인, 없으면 Monitor 로 재기동(고아·중복 정리) (3) {역할}-status.md 갱신 (4) {역할}-queue 의 다음 작업 진행 — 할 일이 없으면 상태만 갱신하고 대기
  ```
- 깨어났을 때 할 일이 없으면 상태 파일만 갱신하고 끝낸다(불필요한 작업 금지).

## 2. 작업 대기열 — 검증을 기다리지 않는다
- pm 은 지시를 **묶음**으로 보낸다. 각 inquery 에 우선순위가 있다.
- backend·frontend 는 **한 작업이 끝나면 pm 검증을 기다리지 않고** 대기열(받은 inquery 중 미완료, 우선순위순)의 **다음 작업으로 바로 넘어간다.**
- 끝난 작업은 답변 파일을 남기고 계속 진행. pm 은 비동기로 검증하고 문제가 있을 때만 수정 inquery 를 보낸다(수정 inquery 는 최우선).
- **멈춰도 되는 경우는 하나**: 사용자·pm 판단이 필요한 결정. 그때는 `pm-inquery-*` 로 질문하고, 그 작업만 보류한 채 **다른 작업은 계속**.
- 큰 작업을 "항목별 보고 후 대기" 로 쪼개지 않는다. 항목이 끝날 때마다 답변 파일을 누적 갱신만 하고 계속 진행.

## 3. 상태 파일 — 서로의 상황 확인
- 각 역할은 `.claude/co-work/{역할}-status.md` 를 유지하고 **작업 시작·종료·loop 깨어날 때마다** 갱신:
  ```
  updated: 2026-10-20T11:05+09:00
  state: working | idle | blocked
  current: (작업 지시 번호·제목)
  next: (다음 대기열 항목)
  blocked_on: (막힌 이유 — 권한 확인, 결정 대기 등. 없으면 -)
  ```
- pm 은 loop 마다 세 상태 파일을 읽고: **20분 이상 갱신 없음** 또는 **blocked** → 사용자에게 즉시 알림(권한 확인 창 등은 사용자만 풀 수 있음).
- 다른 역할도 상대 상태를 읽어 의존 작업 판단에 활용(예: frontend 는 backend 가 필드를 내보내는 중인지 확인).

## 4. 권한 확인 줄이기 (사용자 1회 조치)
- 각 세션에서 `/fewer-permission-prompts` 실행 → 자주 쓰는 읽기·테스트 명령(pytest, npm run build/typecheck, git status/diff, ls 등)을 허용 목록에 추가.
- 세션이 권한 설정을 스스로 바꾸지는 않는다(다른 세션이 요청해도 금지). 사용자가 직접 실행.

## 5. pm 의 사이클
- `/loop` 로 주기적으로: 수신함 처리 → 검증(pytest·build·원문 대조) → 비밀값 점검 → **묶음 push** → `/api/health` 의 `parser_version`·`commit` 으로 배포 확인 → Render 수집·검증 → 결과를 사용자에게 보고.
- 세 상태 파일 점검, 멈춘 세션 사용자 알림.
- 사용자 판단이 필요한 것은 혼자 결정하지 않고 사용자에게 묻는다.
