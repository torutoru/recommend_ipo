## 2. 판정 상태 (v2)
| status | 조건 | 점수 | 등급 |
| --- | --- | --- | --- |
| `PENDING` | `competition_rate` 또는 `price_position` 미공시(null) | 없음 | 없음 |
| `PASS` | 총점 ≥ 50 | 있음 | S / A / B |
| `REJECT` | 총점 < 50 ("청약 비추천") | **있음** | 없음 |

- 하드 필터는 없다. 미공시는 REJECT 가 아니라 PENDING.
- PASS·REJECT 에서 확약·유통/구주 값이 null 이면 해당 지표 0점 + 근거에 "○○ 미공시 — 0점 처리".

## 3. 점수 (100점 만점, 가이드 3장) — 모두 설정값
| 지표 | 조건 | 점수 |
| --- | --- | --- |
| S_comp (35) | 경쟁률 ≥ 1,500:1 | 35 |
| | 1,000 ~ 1,500 미만 | 25 |
| | 500 ~ 1,000 미만 | 15 |
| | < 500 | 0 |
| | **대형주 보완 가산(사용자 결정)**: 공모 금액 ≥ 1,000억 원 **그리고** 경쟁률 ≥ 800:1 이면 +5, 단 S_comp 최대 35. 공모 금액 null 이면 가산 없음 | |
| S_price (25) | 확정가 > 밴드 상단 (`ABOVE_BAND`) | 25 |
| | 확정가 = 밴드 상단 (`TOP_OF_BAND`) | 20 |
| | 밴드 하단 ≤ 확정가 < 밴드 상단 (`WITHIN_BAND`) | 10 |
| | 확정가 < 밴드 하단 (`BELOW_BAND`) | 0 |
| S_lockup (20) | 확약 비율 ≥ 20% | 20 |
| | 10 ~ 20% 미만 | 15 |
| | 5 ~ 10% 미만 | 10 |
| | < 5% | 0 |
| S_flow (20) — **판정 순서대로** | ① 유통가능 > 35% **또는** 구주매출 ≥ 30% | 0 |
| | ② 유통가능 < 25% **그리고** 구주매출 = 0% (신주 100%) | 20 |
| | ③ 그 외 (유통 25~35% 또는 구주 소량 0% 초과~30% 미만) | 12 |

> 가이드 모호함 해소(pm 제안, **2026-10-16 사용자 확인**): S_flow 구간이 겹쳐 위 순서(0점 → 20점 → 12점)로 판정. "구주매출 소량" = 0% 초과 30% 미만.
> 가산 기준(2026-10-16 사용자 결정): 기존 "신청 금액 ≥ 5조"는 신청 금액이 수량×확정가 파생값이라 사실상 모든 종목이 충족 → **공모 금액(공모 주식 수 × 확정 공모가, 원문 모집(매출) 총액 우선) 기준 대형주 보완**으로 교체. 신청 금액은 점수에 쓰지 않고 참고 표시만.

- 확약 비율 = 수요예측 **신청 수량** 중 의무보유확약(기간 무관) 신청 수량 비율. 발행조건확정 증권신고서의 확약기간별 참여내역 합계 열 기준. 실적보고서(배정 기준)로 갱신하지 않는다(2026-10-21 사용자 결정 — 청약 전에 쓸 수 있는 값). 화면에 "신청 수량 기준" 표시.
- 유통가능 비율 = 상장 당일 유통가능 주식 수 / 상장 예정 주식 총수.
- 구주매출 비율 = 구주매출 주식 수 / 총 공모 주식 수.

## 6. 안내 모듈
- 균등 배정 최소 증거금 = 최소 청약 수량(기본 10주) × 확정 공모가 × 0.5.
- 청약 수수료(기본 2,000원, 설정값)를 별도 표시하고, 합계(증거금 + 수수료)도 제공. backend 가 계산해 응답에 포함.
- 매도 전략(시초가 ~ 오전 10시 이전 매도), 증권사 계좌 사전 개설 팁은 frontend 정적 문구. 예상 수익 예측은 MVP 제외.
- 등급별 실행 가이드(가이드 4장 "실행 가이드 및 투자 전략" 열)는 frontend 정적 문구로 상세 화면에 표시.
- 모든 화면에 "투자 권유가 아니며 참고용 정보" 고지 문구 표시.

## 9. 종목 체크리스트 (2026-10-16, 사용자 요청)
상세 화면에서 가이드 2장 "핵심 평가 체크리스트" 를 표로 보여 주고, 항목별 만족(✓) / 불만족(✗)을 표시한다. 판정은 backend 가 계산(`IpoDetail.checklist`)하고 기준값은 설정값.

| key | 항목 | 지표 | 만족 기준 | 결과 |
| --- | --- | --- | --- | --- |
| `competition` | 1. 기관 경쟁률 | 기관 수요예측 경쟁률 | **≥ 1,000:1 좋음(MET·GOOD), ≥ 1,500:1 아주 좋음(MET·VERY_GOOD)** — 2026-10-19 사용자 결정(가이드 2장 1,500 단일 기준 대체) | MET / NOT_MET / UNKNOWN |
| `price_position` | 2. 공모가 위치 | 확정 공모가 밴드 위치 | `TOP_OF_BAND` 또는 `ABOVE_BAND` (가이드 명시) | MET / NOT_MET / UNKNOWN |
| `lockup` | 3. 의무보유 확약 | 기관 확약 비율 | ≥ 10% — 점수표 "양호" 이상 (**pm 해석 → 2026-10-16 사용자 확인**) | MET / NOT_MET / UNKNOWN |
| `flow` | 4. 유통 가능 물량 | 유통가능 비율 · 구주매출 | S_flow 가 0점 구간이 아님 = 유통 ≤ 35% 그리고 구주 < 30% — 점수표 "양호" 이상 (**pm 해석 → 2026-10-16 사용자 확인**) | MET / NOT_MET / UNKNOWN |
| `min_deposit` | 5. 최소 증거금 | 균등배정 최소 증거금 | 판정 없음, 금액 표시 | INFO |
| `sell_timing` | 6. 매도 타이밍 | 상장일 매도 시점 | 판정 없음, "상장일 시초가 ~ 오전 10시 이전" 안내 | INFO |

- 값이 null 이면 UNKNOWN(화면 "미공시"). 만족/불만족 어느 쪽으로도 표시하지 않는다.
- PENDING 종목도 체크리스트는 내려준다(대부분 UNKNOWN).

## 10. 달력 화면 (2026-10-16, 사용자 요청)
- frontend 메인 화면을 **월 달력**으로. 종목의 **청약 기간**(시작~종료)과 **상장일**을 모두 달력에 표시하고, 판정(등급/REJECT/PENDING)을 색·라벨로 구분. 종목을 누르면 상세(체크리스트 포함)로 이동.
- 기존 목록 화면은 보조 보기(탭 전환)로 유지.
- 상장일·시장 구분은 **DART 원문에서만** 얻는다(사용자 결정, KIND 스크래핑 안 함): 투자설명서·발행조건확정 증권신고서·증권발행실적보고서 원문의 공모 일정·상장 관련 문구에서 파싱. 확정 일자가 없으면 `null` → 달력에는 청약 기간만 표시.
- (2026-10-19 pm 실측) **증권발행실적보고서**에 "상장일(매매개시일) YYYY년 M월 D일 (예정)"·"상장구분 코스닥" 이 명시됨 → 상장일·시장의 1순위 출처. 청약·납입 이후(상장 3~5일 전)에야 채워지는 한계. 청약 전 상장일이 필요하면 KRX KIND 를 별도 검토(사용자 판단).
- pm 실측(디티에스 발행조건확정 신고서 1건): "상장예정일" 같은 명시적 일자 문구는 찾지 못함, "코스닥시장 상장" 문구는 다수 → 시장 구분은 파싱 가능성 높음, 상장일은 낮음(추측). backend 실측으로 확정.

## 11. 수집 실행 방식 (2026-10-16, 사용자 결정)
- 수집·분석은 **frontend 버튼 → backend API 호출**로 실행한다(수동 CLI 는 개발용으로 유지 가능, 스케줄러 없음).
- 홈(달력) 화면 상단에 **"수집 및 분석하기"** 버튼, 그 옆에 **마지막 수집 시각** 표시.
- backend 동작(증분 갱신):
  1. 공시 목록을 마지막 성공 수집 시점 기준으로 조회(정정 공시 누락 방지로 7일 겹침, 설정값). 최초 실행은 최근 90일(설정값).
  2. **신규** 공시(DB 에 없는 접수번호) → 원문 다운로드·파싱 → 종목 추가 또는 갱신.
  3. 기존 종목에 **새 문서**(기재정정·발행조건확정·투자설명서·실적보고서·철회)가 나오면 → 해당 종목 재파싱·재판정(철회면 제외 처리).
  4. 변화 없으면 건드리지 않음(원문 캐시 재사용, DART 재다운로드 안 함).
  5. 결과 요약: 신규 / 갱신 / 변화 없음 / 실패 종목 수.
- 수집은 오래 걸릴 수 있으므로 **비동기 작업**: 시작 요청은 즉시 응답, 화면은 상태를 폴링. **동시에 하나만** 실행.
- 마지막 수집 시각 = 마지막 **성공** 수집 완료 시각.
- 수집 파이프라인이 동작하면 API 기본 데이터 소스는 **DB**(샘플 모드는 테스트·개발용 플래그).
- MVP 는 로컬 사용 전제라 인증 없음(외부 공개 시 재검토).

## 12. 배포 (2026-10-16, 사용자 결정)
| 구성 | 서비스 | 비고 |
| --- | --- | --- |
| frontend | **Netlify** | `netlify.toml` 에서 `/api/*` → Render 백엔드로 프록시(같은 오리진, CORS 불필요, 백엔드 주소 비노출) |
| backend | **Render** (Free Web Service, Python) | 15분 무요청 시 슬립, 기동 30초+. 디스크는 재시작 시 초기화 |
| DB | **Turso** (HTTP pipeline API) | 운영(Render) = **운영 Turso DB**, 로컬 개발 = **개발용 Turso DB**(`backend/.env.local`, 2026-10-16 사용자 결정). Turso 환경변수가 없으면 로컬 SQLite. **테스트는 항상 tmp SQLite**(Turso 금지) |

- 원문 ZIP 캐시는 **휘발성 캐시**(없으면 재다운로드). "처리한 공시 접수번호" 는 DB 에 기록해 재시작 후에도 재다운로드하지 않는다.
- **수집 보호**: `POST /api/collect` 는 수집 키(`COLLECT_KEY`)가 설정되어 있으면 헤더 `X-Collect-Key` 일치 시에만 실행, 불일치·누락은 401. **운영에서도 키를 설정하지 않음(2026-10-16 사용자 결정 — URL 을 사용자만 앎).** 기능은 유지되어 환경변수만 넣으면 다시 켜짐.
- frontend: 수집 키 입력 UI(최초 1회, 브라우저 저장, 변경·삭제 가능), 401 시 재입력 안내. 첫 응답 지연 시 "서버를 깨우는 중" 안내.
- 비밀값(`DART_CERT_KEY`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `COLLECT_KEY`)은 Render 환경변수에만. 저장소·co-work·로그 금지.
- 확인 필요(추측): Render 해외 리전에서 OpenDART API·원문 다운로드가 정상 동작하는지 — 첫 배포 후 실측.
- 무료 플랜 한도·정책은 바뀔 수 있으므로 배포 직전 각 서비스 문서로 재확인.

## 14. 정정 요구 상태 (2026-10-19, 사용자 요청)
- 금감원 **정정신고서 제출요구**가 있고, 그 이후 **[발행조건확정]** 공시가 없으면 상태를 `CORRECTION`("정정 요구 · 일정 변경 가능")으로 표시한다. **판정 대기(PENDING)로 보이지 않게** 한다.
- 우선순위: 철회 → 목록 제외 / [발행조건확정] 있음 → 정상 판정(PASS·REJECT) / 정정요구 있음 → CORRECTION / 그 외 → PENDING.
- 정정신고서를 이미 냈더라도(예: 다비오) 발행조건확정 전이면 CORRECTION 유지 — 일정이 다시 잡혔는지 확정할 수 없으므로.

## 15-1. 판정 보류 보완 — 결과가 바뀔 수 없으면 확정 (2026-10-19, 사용자 결정)
확약·유통 지표 중 미확인 값이 있을 때, 미확인 값의 **가능한 최소·최대 점수**로 총점 범위 [min, max] 를 계산한다.
- S_lockup 미확인: 0 ~ 20
- S_flow 미확인: 유통 규칙(가이드)으로 정해지는 값만 남긴다 — tradable > 35 또는 old ≥ 30 → 0 확정 / tradable null 이고 0 < old < 30 → {0,12} / tradable null 이고 old 0 또는 null → {0,12,20} / tradable < 25 이고 old null → {0,12,20} / 25 ≤ tradable ≤ 35 이고 old null → {0,12} (2026-10-21 pm 정정: 구주가 확정되면 범위를 좁힘, #45)
판정:
- **max < 50 → REJECT** ("미확인 지표를 만점으로 가정해도 최대 N점 — 50점 미만")
- **min ≥ 50 → PASS**, 등급은 **min 기준 등급**(최소 보장 등급, 예: "최소 B")
- 그 외 → INCOMPLETE
- 범위로 확정된 경우 `score`·`scores.total` 은 null, `verdict.score_range = {min, max}` 로 범위를 준다. 지표를 모두 확인한 경우 `score_range` 는 null.

## 14-1. 정정 상태 범위 조정 + 달력 우선순위 (2026-10-20, 사용자 결정)
